Tutorial

Tune the parameters.
Rewrite the function.

irace-evo is irace with one addition. While irace tunes the parameters of your algorithm, an LLM writes new versions of one of its functions, and irace races the code together with the parameters. This tutorial goes from the installation to a run on your own code.

1 · The idea

One function, written many ways

You have an algorithm that already works, and irace has tuned its parameters. What still holds it back is often one function: the rule that scores a move, orders the candidates or picks the next component. No parameter value changes that rule. It has to be written differently.

irace-evo sends the source of that function to an LLM, asks for variants, and races them inside irace. In irace a configuration is a set of parameter values, θ. In irace-evo it is a pair: θ and a version A of the function. irace keeps the pairs that win, as it already keeps the parameter values that win.

One function

You name it in a JSON file. The rest of your code never changes.

Always from the original

Every variant is written from your code, never from an earlier variant.

C++, Python, Java

Each variant is built and run once on a test instance before it races. The paper and the example use C++.

Cost

The ten runs in the paper, with Claude Haiku 3.5, cost €1.57 in total.

2 · One iteration

What happens in each iteration

irace works in iterations: it samples configurations, races them and keeps the best ones, the elites. irace-evo adds three steps to each iteration. The diagram shows where they sit, and the list below says what each one does.

  1. irace samples new parameter values, as usual.
  2. The LLM is asked for codeEvolutionVariants versions of the function. Each request starts from the original code. The versions already written in the iteration go into the prompt, so the next one differs from them. In iteration 1 the prompt carries the whole source file. Later prompts carry only the function and the parts of the file it needs.
  3. Each version is compiled and run once on a test instance. A compiler error goes back to the LLM, up to two times. A version that still fails is dropped.
  4. Every new configuration is paired with a version: one of this iteration's, one that an elite already uses, or the original. A configuration keeps its version for the rest of the run.
  5. irace races the pairs and keeps the elites, as usual.

The prompt changes with the iteration. From iteration 3 on (evolution_focus_iteration) it asks for broader structural changes instead of moderate ones.

3 · Install

Install irace-evo

You need R 4.0 or later, Python 3.9 or later and a C++ compiler. On Linux, R builds packages from source, so it also needs Python's shared library and two system libraries. On Debian or Ubuntu:

sudo apt-get install python3-dev python3-venv g++ make libuv1-dev libpng-dev zlib1g-dev

Give the LLM side its own Python environment and tell R to use it, then run the installer from the repository:

git clone https://github.com/camilochs/irace-evo.git
cd irace-evo
python3 -m venv ~/.venvs/irace-evo
export RETICULATE_PYTHON=~/.venvs/irace-evo/bin/python
./install-irace.sh

It installs the R packages irace needs, irace-evo itself, and the two Python packages the LLM side imports (openai and anthropic). It ends by telling you where the irace command is. On a fresh Ubuntu 24.04 machine with R 4.4:

Installed. The irace command is /usr/local/lib/R/site-library/irace/bin/irace; to call it as 'irace':
  export PATH="/usr/local/lib/R/site-library/irace/bin:$PATH"

The R package keeps the name irace, so it replaces an irace you had installed. Keep RETICULATE_PYTHON set (in your shell profile, say) whenever you run irace.

4 · Try it offline

A full run without an API key

Before you spend anything on an LLM, check that the installation works. The repository has a small local server that answers like the OpenAI and the Anthropic APIs. It returns the function it was sent with a comment added, so nothing improves, but every step runs: prompts, compilation, validation, pairing and racing. Then a script reads the run and checks it against the method, one line per check.

tests/evo/run-example.sh anthropic /tmp/evo-run
python3 tests/evo/check_run.py /tmp/evo-run --temperature 1.0 --top-p 0.9

It takes about four minutes and ends with these lines:

The same check also runs for a Python and a Java version of a small knapsack heuristic (run-python-example.sh, run-java-example.sh), and for providers that refuse a parameter, answer with a thinking block first, or fail every call.

5 · A run with Claude

The example with a real model

The offline run showed the steps working. Now the LLM is a real one. examples/tsp-ga-evolution/ holds a C++ BRKGA (a genetic algorithm that encodes a solution as a vector of random keys) for the Longest Run Subsequence problem: pick a subsequence of a string made of runs of equal letters, as long as possible, with each letter in one run at most. irace tunes four parameters. The LLM may rewrite order_chromosome(), which turns a chromosome of random keys into the order the decoder reads it in.

cd examples/tsp-ga-evolution
export ANTHROPIC_API_KEY=...
TIME_LIMIT=5 irace --scenario scenario.txt

TIME_LIMIT is the time of each algorithm run, in seconds. With 5 seconds per run, the whole tuning took about 9 minutes: 4 iterations, 12 calls to claude-haiku-5-5 and 69,449 tokens. All 12 versions Claude wrote compiled, and 11 passed the validation test. The winner is variant_2_iter4 (configuration 21). Here is what irace printed.

6 · Your own algorithm

Four things to prepare

The example you just ran has the four pieces below. For your own algorithm you write each one yourself.

  1. The code. Put your source file and its build where irace runs (execDir), with the original program compiled to bin/<source file name without extension>.
  2. The configuration. Copy inst/templates/code-evolution.json and fill it in (step 7).
  3. The target runner. It reads which program each configuration runs (step 8).
  4. The scenario. Add the three codeEvolution lines and run irace.

Choose a small function that does one thing: a scoring rule, a comparison, an ordering. A function that mixes several parts of the algorithm gives the LLM more ways to break it.

7 · The configuration file

code-evolution.json, section by section

This is the file you copy and fill in. It has seven sections, and the table says what goes in each. The template carries a comment on every option.

SectionWhat it says
problem_contextThe problem and the algorithm in words: name, description, objective, key challenges, domain knowledge. It goes into every prompt.
language_configcpp, python or java.
source_configThe source file and the one function the LLM may rewrite. The prompt tells the LLM to keep the function's signature.
build_configOne section per language: compiler, flags, include paths, libraries. The source file's directory is always on the C++ include path.
llm_configProvider (anthropic or openai), model, temperature, top_p, max_tokens, retries. Leave api_key empty and export the key instead. extra_body passes any request field a provider adds later.
evolution_configevolution_focus_iteration (when prompts turn to broader changes), the strategies used in turn, and how many times a compiler error goes back to the LLM.
validation_configThe command that tests a variant once before it races, its time limit and the pattern its output must match.

8 · The target runner

Running the right program

The target runner is the script irace calls to run your algorithm once. It receives a configuration ID, an instance and the parameter values, as usual. irace-evo writes .irace_evo_variants.csv in execDir, with one line per configuration: config_id,executable_path,variant_id. Your runner looks its configuration up there and runs that program; a configuration not in the file runs the original.

MAPPED=$(awk -F',' -v id="$CONFIG_ID" '$1 == id { gsub(/"/, "", $2); print $2; exit }' .irace_evo_variants.csv)
EXECUTABLE=${MAPPED:-./bin/my-algorithm}
"$EXECUTABLE" -i "$INSTANCE" "$@"

Start from the template target-runner-evolution.tmpl and edit its three marked lines; the example's target-runner is a complete one. Three rules make a runner safe for code an LLM wrote:

Print only the cost

irace reads standard error too; any other line stops the run. Write messages to a log file.

Penalise, never stop

A variant that crashes or prints no cost gets a bad cost, and the tuning goes on.

Limit CPU time

ulimit -t stops a variant that loops forever, however many runs share the cores.

irace minimises, so a runner for a maximisation problem prints the negative of the score, as the example does.

9 · When something fails

Common problems

You seeWhat to do
was not built with a shared libraryR loads Python through its shared library. On Linux install python3-dev and point RETICULATE_PYTHON at a virtual environment made from that Python.
externally-managed-environmentYour system Python does not accept pip installs. Make the virtual environment of step 3.
every call to the LLM failed; the last error was: …The provider refused every call: a revoked key, a retired model, no credit. The message is the provider's own; irace stops instead of racing the original alone.
WARNING: … does not accept ['temperature', 'top_p']Some models refuse these. irace-evo drops what the API names and calls again; nothing to do.
Discarding variant_… : it failed the validation testThe variant compiled but crashed, timed out or printed something else than a number on the test instance. It does not race.

A run deletes what the previous run left in the same folder: variants, their sources and the LLM logs. Copy them elsewhere first if you want to keep them.
